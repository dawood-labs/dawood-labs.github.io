Catching hidden model failures

Two production bugs that looked like good results: a validation split that hid a model's failure, and a date shift that inflated area by 63%.

The problem

A sugarcane model reported excellent scores, and a cotton pipeline produced plausible maps. Both were wrong in ways no metric showed.

Data

  • Sentinel-2 acquisitions across the season
  • Training tables and inference configs

Method

  1. Sugarcane: the static model was trained on seven dates inside one three-week window, with a random per-pixel split. I tested it on other dates: recall fell from 85.0% (10 Aug) to 35.9% (4 Sep)
  2. Rebuilt it with grouped validation, multi-date training and a domain-shift guard
  3. Cotton: the inference window started one step late, so every feature was read 8 days off. Area jumped from 4.63% to 7.57% of the test area
  4. Fixed the dates, added a guard that stops the run if dates do not match training, and wrote tests

Results

  • A date-robust sugarcane classifier with honest validation
  • A cotton pipeline that refuses to run on mismatched dates

What I learned

A high score from a random pixel split is a question, not an answer.

Role

Design, data, modelling, validation and delivery
